## 5.2 模块职责与依赖方向

依赖方向**严格单向**，禁止反向引用：

```
components/  (表现层)
     │  只依赖 store 与 pipeline 的事件
     ▼
store/       (状态)
     │
     ▼
pipeline/    (编排)
     │  只依赖 engines 的接口，不依赖具体实现
     ▼
engines/     (引擎实现)  ←── 这是唯一允许「脏」的地方（各种 SDK 调用）
     │
     ▼
lib/  audio/  (基础能力)
```

| 模块 | 职责 | 禁止 |
|---|---|---|
| `lib/` | 能力探测、缓存、LRU、文本工具 | 不引入 React，不引入业务状态 |
| `audio/` | 只负责「产出干净的 utterance（Float32 16kHz）」，不懂识别 | 不 import 任何 engines/* |
| `engines/*` | 每个文件实现一个引擎接口；可以 import 各 SDK | 不直接操作 store；通过回调向上汇报 |
| `pipeline/` | 编排、降级决策、精修、摘要、健康监控 | 不 import 具体引擎实现，只通过 `registry` |
| `store/` | 纯状态容器与持久化 | 不含业务逻辑判断 |
| `components/` | 渲染与交互 | 不直接 new 引擎 |

**这条边界是「每个环节可独立替换引擎」能成立的唯一保障。**

## 5.3 命名与约定

| 项 | 约定 |
|---|---|
| 引擎实现文件 | `{提供商}{能力}.ts`，如 `webSpeechAsr.ts`、`opusMtWasm.ts`、`textRankSum.ts` |
| 枚举型别 | 用 union type，不用 `enum` |
| 音频单位 | 时长一律 `Ms` 后缀，采样率一律显式写 `16000` |
| 段落 id | `seg_{递增序号}`，精修替换时 id 不变 |
| 错误 | 引擎内抛 `EngineError`，pipeline 捕获后转成 `PipelineEvent.error`，绝不冒泡到 React |
| 未捕获异常 | 全局 `error` / `unhandledrejection` 必须被捕获并展示，**绝不能白屏**（验收标准 §1.5-4） |
| 注释语言 | 中文（面向需求方维护） |
| 提交信息 | 中文，格式 `[模块] 动词 + 对象` |

## 5.4 状态形状（核心 store）

```ts
interface SessionState {
  status: 'idle' | 'probing' | 'preparing' | 'running' | 'summarizing' | 'done' | 'error';
  plan: PipelinePlan | null;        // 每环节实际选用哪一档
  segments: Map<string, FinalSegment>;
  order: string[];                  // 渲染顺序
  partial: PartialSegment | null;   // 当前草稿行
  translations: Map<string, string>;
  summary: SummaryResult | null;
  summaryStream: string;            // 流式摘要的累积文本
  stats: {
    startedAt: number;
    finalCount: number;
    meanLatencyMs: number;
    audioDurationMs: number;
    transcriptDurationMs: number;   // 用于丢句检测
  };
  warnings: string[];
}

interface PipelinePlan {
  asr: { engineId: string; reason: string };
  mt:  { engineId: string; reason: string };
  sum: { engineId: string; reason: string };
  degraded: boolean;
  downloadsRequired: number;        // 预估字节数
}
```

## 5.5 未来可选拆包（一期不做）

只有当 `engines/` 显著膨胀、或需要给第三方复用时，才考虑拆成 pnpm workspace：

```
packages/
  core/        # engines 接口 + registry + pipeline
  engine-asr/
  engine-mt/
  engine-sum/
apps/
  web/
```

**一期明确不拆**——单包最省事，过早拆分只会增加构建复杂度。
