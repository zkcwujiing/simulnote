# V6 评测语料 · 一次典型的英文业务例会（约 10 分钟口播量）
#
# 为什么要有这个文件：docs/06 §6.2 说 V6 要判断「TextRank 能不能挑出真正重要的句子」。
# 光看输出靠人感觉，结论就没法比对、也没法回归。所以这里把语料**先标好**：
#
#   以 "@ " 开头的行 = 人工判定为「这段讲话里真正的要点」
#   其它非空行        = 铺垫、过程描述、闲聊（不该进要点列表）
#   "#" 开头          = 注释，不参与计算
#
# 评测脚本 scripts/summary-bench.mjs 会跑两种喂法：
#   full   —— 去掉 "@ " 前缀后**连标注一起**喂给引擎（对照组，等于答在试卷上，只看匹配算法有没有坏）
#   speech —— **只喂原文行**（诚实档，报告里排前面）
# 然后用「引擎挑出的前 K 句」与人工标注求 precision / recall。
#
# ⚠️ 已知缺陷（2026/10/6，见 docs/results/V6.md 与 docs/07 R4）：
#    这里的标注是**改写**而不是逐字摘录，有些标注甚至比原文更「聪明」
#    （例：@ The board rejected the Northwind acquisition… 对应的原句只是
#     「62 要 95，董事会觉得站不住」，根本没提「董事会否决」）。
#    因此 speech 档的决策/待办命中率偏低里，有一部分是语料构造造成的，
#    不能全记在引擎头上。真要验收「决策抽取」，语料得重做成
#    「先有逐字转写、再从中摘决策」的样子。
#
# ⚠️ 诚实声明：标注只有我一个人做的，是个**弱标准**。它不能证明「摘要好」，
#    但足以回答「TextRank 是不是在乱挑」以及「改动之后有没有变差」。
#    真正上线前仍然要让真人读一遍输出（探针页的 V6 那一节就是干这个的）。
