# 09 · 本地运行与部署

> 这份文档只讲**怎么把它跑起来、怎么发给朋友**。设计依据见 [`03`](03-技术选型与可行性验证.md)、[`08`](08-零成本方案与分享方式.md)。
> 文中标注「实测」的部分都是在 Windows + Node 24/26 + pnpm 11 上真正踩过的坑，照着做可以少走弯路。

---

## 9.1 环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| Node.js | **22 或更高**（实测在 24.21.0 / 26.8.1 上均通过） | `node -v` |
| 包管理器 | **pnpm 11**（实测 11.7.0） | npm 也能装，但本仓库的配置是按 pnpm 写的 |
| 浏览器 | Chrome / Edge 新版（桌面）；手机 Chrome | 需要 `getUserMedia` 与 WebAssembly |
| 网络 | 首次运行需要能访问 `huggingface.co` | 只用于下载模型权重；下载完成后可断网使用 |

---

## 9.2 本地运行

```bash
pnpm install
pnpm dev
```

然后打开 <http://localhost:5173>。

**麦克风的两条硬性前提**（不满足会直接拿不到音频）：

1. **必须是安全上下文** —— `https://` 或 `http://localhost`。
   用 `file://` 双击打开 `index.html` **一定不行**，浏览器会拒绝 `getUserMedia`。
   这就是为什么本项目必须是「一个网站」而不是「一个 HTML 文件」。
2. 首次点击「开始同传」时浏览器会弹权限框；如果之前误点了「拒绝」，要去地址栏左侧的站点设置里改回「允许」。

想在手机上预览本地开发服务器：`pnpm dev` 已经把 `host` 打开，用同一个 Wi-Fi 下的手机访问 `http://<你的电脑 IP>:5173`。
**但注意**：此路径不是安全上下文，麦克风同样会被拒。真机测试请用下面 9.4 的线上地址。

## 9.3 构建

```bash
pnpm build     # tsc -b && vite build
pnpm preview   # 预览 dist/
pnpm verify    # build + lint:cost + lint:size，提交前跑一遍
```

### 实测踩过的构建坑（Windows / pnpm 11）

这几条不是可选项，缺一个就构建不出来：

**① `pnpm-workspace.yaml` 必须写 `nodeLinker: hoisted`。**

Windows 上 pnpm 默认用**目录联接（junction）**实现 `node_modules` 链接。Node 的 ESM 解析器用的是 JS 版 realpath，**不解析 junction**，于是从 `node_modules/vite/dist/…` 往上找 `rollup` 时会走到真实顶层目录，那里没有 rollup，报：

```
Error [ERR_MODULE_NOT_FOUND]: Cannot find package 'rollup'
    imported from D:\同声传译项目\node_modules\vite\dist\node\chunks\config.js
```

改 `nodeLinker: hoisted` 后 `node_modules/rollup` 会直接出现在顶层。

**这一步必须写在 `pnpm-workspace.yaml` 里，不能写在 `.npmrc` 里。** pnpm 11 已经**不再读取** `.npmrc` 的 `node-linker` 设置（`pnpm config get node-linker` 会返回 `undefined`，装完仍是 isolated 布局）。

**② 构建脚本的 allowlist 也在 `pnpm-workspace.yaml`，键名是 `allowBuilds`。**

pnpm 11 不再读 `package.json` 里的 `pnpm.onlyBuiltDependencies`（会警告 `The "pnpm" field in package.json is no longer read by pnpm`）。本项目把三个依赖的构建脚本都设为 `false`：

```yaml
allowBuilds:
  esbuild: false
  onnxruntime-node: false
  protobufjs: false
```

esbuild 设为 `false` 是安全的：pnpm 已通过 optionalDependencies 装好了 `@esbuild/win32-x64`，它的 postinstall 只是校验/补下载，关掉不影响使用。

**③ 如果构建时 `esbuild` 报 `spawn EPERM`。**

这是**受限沙箱**造成的（程序无法用管道 stdio 启动子进程），不是配置错误 —— 换写法、换参数、`--preserve-symlinks` 都没用。解决办法是让构建在不受限的环境里跑（普通终端、CI，或提升权限）。

**④ 如果构建时 esbuild 报 `remove C:\Users\...\Temp\esbuild-xxxx: Access is denied`。**

把临时目录指到项目内即可：

```powershell
$env:TEMP='D:\同声传译项目\.tmp'; $env:TMP=$env:TEMP
New-Item -ItemType Directory -Force -Path $env:TEMP | Out-Null
pnpm build
```

`.tmp/` 已在 `.gitignore` 里。

**⑤ Tailwind v4 的 `@apply` 不能引用自定义组件类。**

`@apply btn bg-brand-500` 这种写法在 v4 会直接构建失败：

```
[@tailwindcss/vite:generate:build] Cannot apply unknown utility class 'btn'
```

所以 `src/index.css` 里的 `.btn / .btn-primary / .card` 等全部是**纯 CSS**（用逗号选择器共享基础声明），只有 `@theme`、`@utility` 是 Tailwind 语法。新增样式时请沿用这个约定。

## 9.4 部署：路线 A（同一份构建，两个链接）

设计动机见 [`08`](08-零成本方案与分享方式.md)：国内和朋友各有一半概率打不开某一个平台，所以**同时部署两个，两个链接都发出去**，哪个能开用哪个。

### 前置：把代码推到一个 GitHub 仓库

两个 workflow 都在 `.github/workflows/` 下：

| 文件 | 目标 |
|---|---|
| `deploy-pages.yml` | GitHub Pages（`VITE_BASE=/<仓库名>/`） |
| `deploy-cloudflare.yml` | Cloudflare Pages（`VITE_BASE=/`） |

### 9.4.1 GitHub Pages（推荐主链接）

1. 推送代码到 `main`。
2. 仓库 **Settings → Pages → Build and deployment → Source** 选 **GitHub Actions**。
3. `deploy-pages.yml` 会自动跑，地址形如
   `https://<用户名>.github.io/<仓库名>/`。

免费额度：站点 ≤1 GB、软带宽 100 GB/月。**没有单文件大小限制**，所以 26.8 MB 的 wasm 可以直接托管。

> `VITE_BASE` 必须设成 `/<仓库名>/`。项目站部署在子路径下，base 写错的话页面会白屏、控制台一堆 404 —— 这是 GitHub Pages 项目站最经典的坑。

### 9.4.2 Cloudflare Pages

1. 在 Cloudflare 控制台建一个 Pages 项目（**Direct Upload** 模式，名字与 workflow 里的 `--project-name=simulnote` 保持一致）。
2. 仓库 **Settings → Secrets and variables → Actions** 加两个 secret：
   - `CLOUDFLARE_API_TOKEN`
   - `CLOUDFLARE_ACCOUNT_ID`
3. 推送后 `deploy-cloudflare.yml` 会自动跑，地址形如 `https://simulnote.pages.dev/`。

免费额度：20,000 个文件、500 次构建/月、带宽不计量。**但单文件上限 25 MiB。**

### 9.4.3 ⚠️ 25 MiB 这个坑，以及它的两种解法

`transformers.js` 会让构建产物里出现一个

```
dist/assets/ort-wasm-simd-threaded.asyncify-CxOG5pUO.wasm     26,861,777 字节（25.62 MiB）
```

**超过了 Cloudflare Pages 的 25 MiB（26,214,400 字节）单文件上限**，Cloudflare 会直接拒绝这次部署。
GitHub Pages 没有这个限制。CI 里有一道闸门 `scripts/check-upload-size.mjs`，会在上传前就把话说清楚，而不是让你去猜云厂商那句报错：

```
以下文件超过单文件上限，Cloudflare Pages 会拒绝这次部署：
  - assets\ort-wasm-simd-threaded.asyncify-XXXX.wasm  25.62 MB（超出 0.62 MB）
```

**解法一（省事，推荐先用这个）**：Cloudflare 那一半先不部署，**只发 GitHub Pages 的链接**。功能完全一样，零成本承诺也完全成立。

**解法二（两个源站都完整）**：把 wasm 外置成本仓库自己的 GitHub Release 资产。Release 资产同样免费、无需付费账号。步骤：

1. 构建一次，找到那个 wasm：

   ```powershell
   pnpm build
   Get-ChildItem dist -Recurse -Filter *.wasm | Select-Object FullName, Length
   ```

2. 在 GitHub 上建一个 Release（tag 任意，例如 `wasm-v1`），把那个 `.wasm` 传上去。
   注意上传后**保持文件名不变**。
3. 仓库 **Settings → Secrets and variables → Actions → Variables → New repository variable**：

   ```
   Name : VITE_ORT_WASM_BASE
   Value: https://github.com/<你>/<仓库>/releases/download/wasm-v1/
   ```

   **结尾那个 `/` 不能少**（ORT 拿它做字符串拼接）。
4. 重新跑 `deploy-cloudflare.yml`。

原理：`vite.config.ts` 里的 `ortWasmPolicy` 插件在检测到 `VITE_ORT_WASM_BASE` 时，会把超过 12 MiB 的 `.wasm` **从产物里删掉**；运行时由 `src/lib/ortEnv.ts` 把这个基址交给 ONNX Runtime，让它去那里取 wasm。

> 两个开关必须成对使用：只删文件不设基址 → 本地模型加载失败；只设基址不删文件 → Cloudflare 上传被拒。
> 不设这个变量时，默认行为完全不变（wasm 正常打进站点）。

验证外置是否生效：

```powershell
$env:VITE_ORT_WASM_BASE='https://github.com/example/simulnote/releases/download/wasm-v1/'
pnpm build
(Get-ChildItem dist -Recurse -Filter *.wasm | Measure-Object).Count   # 期望 0
```

### 9.4.4 发给朋友

- 把两个链接都发过去，说明「哪个能打开就用哪个」。
- 网站上点「分享」会**在本机生成二维码**（`src/components/ShareCard.tsx`），可以直接截图发给朋友。
  二维码是本地算的，**不会把你的网址发给任何在线二维码服务**。

## 9.5 排查

| 现象 | 原因 / 处理 |
|---|---|
| 点「开始同传」没反应 | 地址不是 `https` 或 `localhost`；或之前拒绝了麦克风权限 |
| 微信里打不开麦克风 | 微信内置浏览器限制较多，右上角「在浏览器中打开」 |
| 页面白屏 | 多半是 `VITE_BASE` 与部署子路径不匹配（GitHub Pages 项目站常见） |
| 一直卡在「正在检测浏览器能力」 | 该浏览器不支持 WebAssembly 或不是安全上下文，看卡片里的中文原因 |
| 下载模型很慢 | 模型来自 Hugging Face；国内网络可能需要代理。**这是目前体验上最大的不确定项** |
| 手机上很卡或标签页崩溃 | 本地模型对手机内存压力很大（[`07`](07-风险与对策.md) R1）。改用「最快启动」模式（走浏览器原生识别，零下载） |
| 翻译里数字明显错 | 已知问题（R4）。**看纪要里的「关键数字」表** —— 那张表是从英文原文抽的，不经过翻译模型 |

## 9.6 免费额度的边界（记在脑子里，别踩线）

| 平台 | 硬限制 | 本项目是否受影响 |
|---|---|---|
| GitHub Pages | 站点 ≤1 GB、软带宽 100 GB/月、软限制 10 builds/小时（用自定义 Action 构建不受此限） | 当前产物约 27 MB，**远未触顶** |
| Cloudflare Pages | 20,000 文件、**单文件 ≤25 MiB**、500 builds/月、带宽不计量 | **受 25 MiB 限制**，见 9.4.3 |
| 腾讯 EdgeOne Pages | 默认域名只有 **3 小时**有效期，且需备案 | 不采用 |

如果哪天流量涨到触顶，方案是「多平台兜底」而不是付费：把同一份 `dist/` 同时传到 GitHub Pages、Cloudflare Pages、Netlify、Vercel 等免费额度，链接轮换着发（见 [`08`](08-零成本方案与分享方式.md)）。
