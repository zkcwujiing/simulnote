# 10 · 上线清单（照着做就行）

这篇只有一个目的：**把已经写好的代码变成一个手机能打开的 https 链接。**
不需要先读别的文档，按顺序做完这 6 步即可，全程免费、不需要信用卡。

代码这边已经全部就绪 —— 本地仓库有提交、`.gitignore` 挡住了 513 MB 的包缓存、
GitHub Actions 工作流也写好了（它会自己把模型权重拉下来一起发布）。
**缺的只是「一个远程仓库地址」和「按下 push」。**

> ✅ **本项目已经上线了**：<https://zkcwujiing.github.io/simulnote/>
> （探针页 <https://zkcwujiing.github.io/simulnote/probe.html>）
> 下面这份清单是给「换一台机器、换一个仓库重新走一遍」时用的。

> 📌 关于模型：**模型权重的文件不进 git**（否则仓库会有 160 MB，push 一次要等很久）。
> 它们由 `scripts/fetch-models.mjs` 在**构建期**下载到 `public/models/`，再随站点一起发出去。
> 你在 GitHub Actions 里什么都不用配 —— 工作流已经带了这一步，而且把结果缓存起来了。

---

## 第 0 步 · 上线前自检（约 1 分钟）

在项目目录里跑：

```powershell
pnpm verify
```

它依次做四件事：**模型本地体检** → `tsc -b`（类型检查）→ `vite build`（构建）→
零成本护栏扫描 → 体积闸门。

期望结果：以 `通过` 结尾、退出码 0。最后体积闸门会**以警告形式**列出几个超过
25 MiB 的文件（26.8 MB 的 ONNX Runtime wasm + 三个模型 `.onnx`）——
**那是预期的，不是错误**：GitHub Pages 没有单文件大小限制，这些文件只有
Cloudflare Pages 才收不下。那段警告里也写明了这一点。

> ⚠️ 如果你是在**一台新克隆的机器**上跑，第一次会先报
> `模型自托管 —— 本地体检不通过：0/24 个文件`。
> 这不是 bug，是在提醒你先跑一次 `pnpm fetch-models` 把模型拉下来（约 160 MB，
> 只需一次）。CI 上不用管，工作流自己会跑。

---

## 第 1 步 · 在 GitHub 建一个空仓库

- 打开 <https://github.com/new>
- 仓库名填 `simulnote`（或任何你喜欢的名字，**但记住它**，第 4 步的网址要用）
- 可见性：**Public**（私有仓库的 GitHub Pages 需要付费账号，所以选 Public）
- **不要**勾选 "Add a README file"、不要选 .gitignore 模板、不要选 license
  —— 本地已经有这些文件，勾了会造成首次 push 冲突

---

## 第 2 步 · 关联并推送（三条命令）

把 `<你的用户名>` 和 `<仓库名>` 换成实际值：

```powershell
cd D:\同声传译项目
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

推送时会弹出 GitHub 登录窗口（或要求输入 Personal Access Token）。
如果它抱怨 `remote origin already exists`，说明之前加过，改成：

```powershell
git remote set-url origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

> 为什么是 `main`：本地分支就叫 `main`，两个工作流都监听这个分支。

---

## 第 3 步 · 打开 GitHub Pages

- 进入仓库页面 → **Settings** → 左侧 **Pages**
- **Source** 选 **GitHub Actions**（不要选 "Deploy from a branch"）

这一步只需做一次。之后每次 push 到 `main` 都会自动重新部署。

> ⚠️ **这一步没法由工作流代劳，必须手动点。** 实测把
> `actions/configure-pages@v5` 配上 `with: enablement: true` 也不行，
> 它会以这个错误收场：
>
> ```
> Create Pages site failed. Error: Resource not accessible by integration
> Get Pages site failed. Error: Not Found
> ```
>
> 原因是**创建 Pages 站点需要仓库管理员权限，而 CI 拿到的 `GITHUB_TOKEN`
> 永远不会有这个权限**（它只有 `pages: write`，那只能操作已存在的站点）。
> 判断站点开没开可以直接查 API：
>
> ```powershell
> Invoke-WebRequest -UseBasicParsing https://api.github.com/repos/<用户名>/<仓库名>/pages
> ```
>
> `has_pages=false` / 404 就是没开，工作流一定会在 `configure-pages` 那一步红掉，
> 而它前面的 Install / Fetch models / Build 全都是绿的 —— 看到这种「只红最后一步」
> 别怀疑代码，去 Settings → Pages 点一下就行。开关打开之后**重跑一次**
> （Actions 页面点 "Re-run failed jobs"，或推一个空提交
> `git commit --allow-empty -m "chore: 重新触发部署"`）即可。

---

## 第 4 步 · 等 Actions 跑完，拿到网址

- 进入仓库页面的 **Actions** 标签，看 `Deploy to GitHub Pages` 那条跑成绿色
- **首次**大约 4–8 分钟：要装依赖、构建，还要从 Hugging Face 拉 24 个模型文件（约 160 MB）。
  这一步的结果会被 Actions 缓存起来，**之后每次 push 只要 2 分钟左右**。
- 如果日志里看到 `Fetch models（约 160MB，随站点发布）` 这一步在慢慢下载，那是正常的

网址的形态是：

```
https://<你的用户名>.github.io/<仓库名>/
```

例如仓库叫 `simulnote`、用户名是 `zhangsan`，就是
`https://zhangsan.github.io/simulnote/`。

**本项目实测**：用户名 `zkcwujiing`、仓库 `simulnote`，所以网址是
`https://zkcwujiing.github.io/simulnote/`。首次运行流水线
（`5b4ad35` 与 `addeece` 两次）都卡在 `configure-pages`，按第 3 步手动开 Pages 后，
第三次（`6aaec4c`）build 与 deploy **两个 job 全绿**，站点随即 200。

**构建时已经自动注入了 `VITE_BASE=/<仓库名>/`**，所以你不需要手动改任何路径。
如果打开是白屏，99% 是仓库名和网址里的子路径对不上，见下面第 7 步。

---

## 第 5 步 · 手机上先开探针页，再开主页面

**先开这个**（注意网址后面多了 `probe.html`）：

```
https://<你的用户名>.github.io/<仓库名>/probe.html
```

点「跑全部零下载项」，重点是 **V8 内存压力测试**和**设备画像**。
它会告诉你这台手机的真实上限，跑完可以复制成 Markdown 报告。

**再开主页面**：

```
https://<你的用户名>.github.io/<仓库名>/
```

第一次录音时它会提示要加载模型，点一下才开始。**模型不是从 Hugging Face 下的 ——
它就是你这个站点自己的文件**（`/models/Xenova/whisper-tiny.en/...`，约 42 MB，
加上翻译模型约 117 MB，合计 160 MB 左右）。

> 为什么非要这样：实测在普通家宽、无代理的情况下，`huggingface.co` **0/3 完全不通**
> （DNS 被污染），`cdn-lfs.huggingface.co` 的 443 端口也不通 —— 而模型权重正是存那儿。
> 如果让浏览器直接去 HF 下模型，站点部署得再好，用户也会卡在「正在下载模型」，
> 最后退化成「只转写、不翻译」。把模型并进站点之后，**运行时零外部依赖**，
> 你和朋友都不需要任何代理。代价是首次打开要多下 160 MB（走 GitHub Pages 的 CDN）。

> ⚠️ **必须用 `https://` 打开**，别用 `http://`。麦克风只在安全上下文里可用，
> 局域网访问（`http://192.168.x.x:5173`）在手机上一定拿不到麦克风。

---

## 第 6 步 · 把链接发给朋友

主页面底部有「分享」按钮，会**在本机生成二维码**（不调用任何在线二维码服务，
否则等于把网址交给第三方）。也可以直接用手机自带的「添加到主屏幕」——
`apple-touch-icon.png` 和 manifest 都已经配好，加完就是一个独立图标。

---

## 第 7 步 · 出问题时的对照表

| 现象 | 最可能的原因 | 怎么办 |
| --- | --- | --- |
| 打开是白屏，控制台一堆 404 | `VITE_BASE` 和实际子路径对不上 | 确认仓库名与网址里的路径一致；如果是 `<用户名>.github.io` 这种用户站，把工作流里的 `VITE_BASE` 改成 `/` |
| Actions 报 `pnpm install --frozen-lockfile` 失败 | `pnpm-lock.yaml` 没提交 | 本地 `git status` 看它是否被跟踪；它应该在，不在就 `git add pnpm-lock.yaml` 后重推 |
| 页面能开，但点「开始」说没有可用的识别方案 | 不是 https，或浏览器不支持 | 确认地址是 `https://`；安卓用 Chrome、iOS 用 Safari 16.4+ |
| Actions 停在 `Fetch models` 很久 | 首次要下约 160 MB 模型并写进缓存 | 正常，等它跑完；之后每次构建都命中缓存，不再重下 |
| Actions 的 `Fetch models` 报错 | 构建机两个源都拿不到模型 | 重跑一次即可（脚本会跳过已下好的）；连续失败就把 `public/models/` 整个传到本地再重推 |
| 本地 `pnpm build` 报 `本地体检不通过：0/24 个文件` | 新克隆的仓库里 `public/models/` 是空的（它不进 git） | 先跑一次 `pnpm fetch-models` |
| 一直卡在「加载模型」 | 站点自己的 `models/` 拿不到（多半是子路径不对，404） | 浏览器控制台看有没有 `/models/...` 的 404；确认仓库名与网址子路径一致 |
| 手机录音几分钟后页面被系统杀掉 | 内存不够（V8 还没测过） | 这正是第 5 步要先跑探针的原因；结果出来后按 `docs/06` §6.4 调手机档引擎组合 |
| 分享到微信没有预览图 | 抓取器缓存了旧卡片 | 确认 `og:image` 已是绝对地址（构建时由 `VITE_SITE_URL` 注入）；换一个链接参数强制刷新抓取 |

## 可选 · 第二个源站（Cloudflare Pages）

`deploy-cloudflare.yml` **故意设成只能手动触发**：它需要 2 个 secret 和 1 个变量，
没配齐时必然失败，跟着 push 跑只会让 Actions 页面变红。

**暂时不建议开**，因为 Cloudflare Pages 有 25 MiB 单文件上限，而现在产物里有 **4 个**文件超限：

| 文件 | 大小 | 能不能外置 |
| --- | --- | --- |
| `assets/ort-wasm-simd-threaded.asyncify-*.wasm` | 25.62 MiB | ✅ 可以（传到本仓库的 GitHub Release 资产） |
| `models/Xenova/opus-mt-en-zh/onnx/decoder_model_merged_quantized.onnx` | 57.42 MiB | ❌ 目前没有方案 |
| `models/Xenova/opus-mt-en-zh/onnx/encoder_model_quantized.onnx` | 50.45 MiB | ❌ 目前没有方案 |
| `models/Xenova/whisper-tiny.en/onnx/decoder_model_merged_quantized.onnx` | 29.30 MiB | ❌ 目前没有方案 |

也就是说：wasm 那条老办法已经**不足以**让 Cloudflare 跑起来了 —— 自托管模型
本身就是几十 MB 一个。要在 Cloudflare 上跑，得先把 `scripts/fetch-models.mjs`
的清单砍小（比如只留 whisper、去掉翻译模型），那会牺牲功能。
**GitHub Pages 没有单文件上限，所以这是唯一无损的路线，也是默认路线。**

完整做法写在 `docs/09-本地运行与部署.md` §9.4.3 与 `docs/07-风险与对策.md` R13。

真要开的时候按这个顺序：
1. Settings → Secrets and variables → Actions 里加 secret `CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID`
2. 把 wasm 传成 Release 资产，加 Variable `VITE_ORT_WASM_BASE`（形如 `https://github.com/<你>/<仓库>/releases/download/wasm-v1/`）
3. 可选：加 Variable `VITE_SITE_URL`（形如 `https://simulnote.pages.dev/`）
4. Actions → `Deploy to Cloudflare Pages` → Run workflow
